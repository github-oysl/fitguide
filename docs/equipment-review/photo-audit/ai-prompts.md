# 给其他 AI 的动作检索、准确性核验与入库提示词

## 使用方式

按顺序运行：**器械身份 → 动作研究 → 独立核验 → 数据草稿**。已有明确类别的器械可直接研究，但仍应带上原图和未决项。不要只给 AI 一个“腿举”或“推胸”的中文名字。

每次建议研究 1–3 个动作，提供：

- [equipment-inventory.md](equipment-inventory.md) 中对应 E 编号的完整档案及原图；文字清单不能替代图像输入。
- [exercise-catalog.md](exercise-catalog.md) 中该动作、变式、附件条件和现有 ID。
- [sources.md](sources.md) 作为已经查过的入口，但明确这些来源并不都是本机型号说明。
- 若需要兼容现有网页，再提供 `data.js`、`extra-data.js` 的实际对象或示例。

先把下方花括号占位符替换为实际内容，再交给目标 AI。若目标 AI 无法看图或联网，应让它输出缺失项，不要让它凭记忆声称已经核验。

## 提示词 A：复核器械身份、机型与去重

```text
你是健身器械资料审核员。请只对证据支持的器械身份下结论，不追求把所有照片强行命名。

输入：
器械档案：{粘贴 E 编号完整条目}
原始照片：{提供该组全部图片，保留文件名和编号}
已知铭牌文字：{可读文字；不可读则写未知}
现有候选：{候选名称；没有则留空}

任务：
1. 逐图记录你真正看见的结构：座位、靠背或胸托、肩垫、压腿垫、滚垫、脚撑、
   滑轮出线位置、导轨、工作臂、转轴、配重方式、握把、调节机构。
   区分“照片可见”“依据结构推断”“未见”。不要把照片没拍到说成不存在。
2. 逐字抄录清晰铭牌；模糊字标[不可读]，不得补全品牌型号。
3. 给规范中文名、英文名、器械功能族、具体子型、候选替代身份和证据等级。
   若不能区分推胸/肩推、胸托/靠背、下拉/高位划船，保留待定。
4. 联网优先查铭牌制造商的官方说明书，其次官方产品页或专业机构。
   其他品牌的相似图只证明一种结构存在，不能用来确认本机型号。
   必须打开正文，不以搜索摘要、图片标题、商城标题或另一AI回答作为完成核验。
5. 核对双功能是否有明确铭牌、换向机构和两种负重模式。
   不能把负重回程当成反方向独立训练；不能自动允许反坐或换方向使用。
6. 对照片去重分三层：完全相同文件、同机多角度、同类不同实例。
   组合架不同工位、镜像、相邻设备和铭牌近照要分别说明。
   原照片一律保留，只做档案映射；未有文件哈希时不得宣称字节相同。
7. 身份仍不明时，指出最小补充证据，例如“动作牌近照+侧面工作臂全景”。
   不要求使用者带负重试做来验证你的猜测。

输出：
- 结论：confirmed-category / probable / unresolved；型号另标 confirmed / unknown。
- 照片编号→器械ID映射、同机关系与依据、候选排除理由。
- 证据表：判断 | 照片可见细节 | 来源URL/说明书页码 | 推断范围 | 未解决项。
- 能确认的基础功能、条件扩展功能、目前不可确认的功能。
准确度优先于数量；不编造名称、型号、承重、空车重、滑轮倍率或操作步骤。
```

## 提示词 B：检索并编写一个动作的知识草稿

```text
请为健身动作知识库研究下面一个动作，输出中文 Markdown 和结构化草稿。
这不是给具体个人制定训练处方；不要补写输入中没有的人群条件。

输入：
器械ID/档案/实拍图片：{完整输入}
动作名称和现有ID：{名称、ID或新增候选}
动作版本：{坐姿/俯卧/站姿；挂片/钢索；胸托/无胸托；握法}
现场附件：{已见、待确认的附件分别列出}
尚未确认的问题：{从器械档案原样复制}
来源入口：{sources.md 对应 S编号；可补充新来源}

研究流程：
1. 先判断此动作与实拍结构是否匹配。器械身份不明时停止专机操作编写，
   输出 needs-equipment-confirmation，而不是自行选择候选。
2. 同时检索中文别名和英文标准名称。先查原机官方说明/演示；
   再查 ACE、NSCA 或同等专业机构的具体动作页；训练效果争议查原始研究。
   至少尽量取得“器械功能证据”和“动作技术证据”两条证据链。
   两条网址若只是转载同一来源，不算独立证据；找不到就说明未完成。
3. 打开每个实际采用的页面/视频。记录标题、机构、URL、访问日期，
   说明书页码或视频时间戳，以及具体支持的断言。
   未看视频不要声称视频姿势已匹配。仅目录页不支持完整动作步骤。
4. 分开记录机器功能、通用动作技术、训练效果三种证据。
   厂家营销词不当作肌肥大或关节风险的研究结论。
5. 对每条步骤和肌群结论写 claimId，并关联来源。
   区分主动动力肌、协同肌、稳定肌，不把示意图着色当作完整肌肉证据。
6. 冲突时比较是否同机型、同姿态、同动作目标；保留冲突和适用范围。
   不机械地按多数网站或“权威名称”投票。

必须输出的动作卡：
- 中英文名、别名、稳定ID、动作族与具体变式。
- 适用器械ID、必需附件、适配状态 applicable/conditional/unresolved 及理由。
- 主要关节动作、主要肌群、协同与稳定肌群，逐项证据。
- 开始前设置：身体支撑、座垫/背垫、膝轴/滚垫、握把/滑轮、必要安全装置。
  原机未知的数值、档位、插销次序写 unknown，不填其他型号参数。
- 准备、发力、还原、结束退出四阶段；每阶段写可观察行为与依据。
- 舒适受控的动作范围和呼吸提示，不把某角度写成所有人的硬性要求。
- 常见错误→如何识别→纠正提示；区分允许的肩胛运动与躯干代偿。
- 需要暂停并检查设置的情况；无病史时不编造康复或疾病禁忌。
- 一句话提示 cue，避免“完全隔离”“局部减脂”“膝盖绝不能过脚尖”等无依据绝对话。
- 可扩展动作：每个列出新增模式/附件/空间/厂家许可，分别说明证据。
- 图/视频要求：同姿势、同支撑、同阻力形式、同附件，给关键帧要求；
  AI生成图片不能作为技术正确性的证据，也不能直接认定可公开再分发素材。
- 组数、次数、休息、负重与进阶：没有目标人群与证据就填 null；
  若提供通用参考，必须写适用前提并引用来源，不统一复制 3×12。

最终状态只能是 research-draft / needs-evidence / ready-for-independent-review。
请最后列出“已证实”“合理推断”“未证实”三张清单。
不能用一句“请咨询教练”替代尚未完成的具体研究。
```

## 提示词 C：独立校验知识和媒体是否准确

最好开一个新对话或使用另一个 AI，重新提供原图与草稿，避免只让生成者自我确认。

```text
你是独立审核员。下面是另一AI写的健身动作草稿，请寻找具体错误和证据缺口。
不要因为文字流畅、附有链接或说“已核验”就默认正确。

输入：
原始器械照片及档案：{输入}
动作研究稿及逐条 claimId：{输入}
全部来源和媒体：{输入URL/文件}

请逐项执行：
A. 身份一致性：照片→器械类别→具体子型→动作姿态→媒体是否完全对应？
   特别检查：俯卧/坐姿弯举；水平/斜轨腿举；腿举/哈克；钢索/挂片下拉；
   高位划船/下拉；胸托/无胸托划船；肩推/上斜胸推；把手/前臂垫夹胸。
B. 来源有效性：亲自打开采用的原始页面；断言是否真的在正文？
   引用是否只支持不同品牌型号？视频是否实际看过对应片段？
   是否有伪造链接、失效页、只有搜索摘要或把目录当动作指南？
C. 生物力学：关节动作、负重方向、动力肌与稳定肌是否一致？
   是否把伸肘下压写成肩伸展，把髋后蹬写成屈膝，或把外展回程算内收？
D. 机器设置：转轴、滚垫、固定垫、模式与身体接触点是否有依据？
   辅助配重是否被误写为附加负重？是否抄入别的机器的档位、空车重、倍率？
E. 扩展适配：是否已确认所需附件、模式、行程和空间？
   腿举提踵、反坐飞鸟、单腿/单臂、反向哈克等有无本机支持证据？
F. 表述和剂量：是否含无依据的绝对角度、局部减脂、保证增肌、
   用EMG结果直接证明长期增肌优越性，或把通用方案当成个人处方？
G. 媒体：如可访问，逐关键帧核对准备/发力/还原/退出的接触点与运动方向。
   模型/姿态检测只能辅助观察，不能代替对机器结构和动作意义的判断。

输出表格：
claimId | 草稿原句 | 通过/需限定/错误/证据不足 | 依据URL与页码/时间戳 |
错误解释 | 可直接替换的修订文字 | 对入库的影响

严重程度：
- blocker：器械/姿势错配、关键安全装置或重量方向错误、来源捏造。
- major：关键操作无证据、附件/模式未确认却标可用、肌群或动作方向错误。
- minor：不会改变操作含义的用词或格式问题。

最终只给 pass / revise / blocked 三选一，并列所有未解决项。
有 blocker 或影响动作执行的 major 时不可 pass。
如果只验证了通用技术但缺少现场模式证据，保持 conditional，不伪装成全面通过。
另一个AI同意草稿本身不是证据；审核必须回到原图和可核验来源。
```

## 提示词 D：生成兼容网页的待审核数据

```text
把下面已独立审核的动作转换为 FitGuide 待审核数据草稿。
只生成 Markdown 中的 JSON，不改网页文件，不下载/覆盖现有素材。

输入：
审核通过的动作与 claimId/source 对照：{输入}
实际现有动作对象和枚举：{从 data.js / extra-data.js / guide.js 提供}
器械ID与变式ID：{输入}
现场适配审核结果：{输入}

要求：
1. 已有同一动作保持原ID，避免破坏训练计划和打卡关联；
   姿态、支撑或动作意义不同的版本另建ID/variant，先给迁移建议。
2. 保留现有字段的语义。category、muscles、equipment 的值必须来自真实代码，
   不要猜新枚举已经受页面支持。新增值单列“需要代码支持”。
3. 追加审计层保存 equipmentIds、variantId、必需附件、现场适配状态、
   evidence、claim/source 对照、未解决项与review；这些是建议扩展，不声称页面已经识别。
4. availability 的用户文案和审计状态分开。附件未确认则写条件具备，
   不能因动作通用可做就写本健身房已确认。
5. source 字段只取直接支持动作的页面；完整多来源放审计层。
   不因有旧本地文件就把 localDemo 设 true，必须先核对媒体版本和文件存在。
6. 参数未知填 null，不能补造具体型号、座位档位、重量、训练剂量。
7. 输出：建议复用/新增ID、JSON草稿、待代码支持的字段、尚需补齐的内容。
   任何 blocker 未解决，则只输出 blocked 和缺失项，不输出“可发布”的对象。
```

## 建议审计记录（独立于当前页面字段）

以下是结构示例，**不是已完成核验的动作数据**。`category`、`muscles` 等网页枚举应从当前代码读取。

```json
{
  "exerciseId": "prone-leg-curl",
  "variantId": "selectorized-prone",
  "equipmentIds": ["E24"],
  "name": "俯卧腿弯举",
  "englishName": "Prone Leg Curl",
  "photoEvidence": [45, 47],
  "identity": {
    "categoryStatus": "confirmed-category",
    "brandTextObserved": "POWER MEGA MASS",
    "manufacturerIdentity": null,
    "model": null
  },
  "compatibility": {
    "status": "conditional",
    "requiredAttachments": [],
    "requiredChecks": ["确认膝轴与滚垫设置及该机型调节方式"]
  },
  "claims": [
    {
      "id": "C01",
      "text": "照片47铭牌可读Prone Leg Curl，照片45为俯卧支撑结构",
      "evidenceType": "photo",

    }
  ],
  "sources": [],
```

配重辅助型 E11 的审计层还应记录 `loadMeaning: assistance`；普通阻力机器可以用 `resistance`；不明机器用 `unknown`。这是建议的数据语义，当前网页不一定有相应逻辑。

## 发布前验收清单

- [ ] 器械ID和原始照片可追溯，照片与动作子型一致。
- [ ] 附件、模式和关键设置有证据；没有将待定项转换为已确认。
- [ ] 每项关键技术断言能找到真正支持它的原始来源。
- [ ] 未把其他品牌的参数写进本机说明，没有编造型号或安全装置操作。
- [ ] 图片／视频动作姿势与器械版本一致；可访问性与使用权限分别核验。
- [ ] 独立审核无 blocker，影响执行的 major 已解决。
- [ ] 现有ID未被错误复用；新枚举和审计字段没有假装受现有前端支持。
- [ ] 条件适用、动作技术审核、媒体审核分别记录，均有日期与未决项。

满足多少条就记录多少条，不自动勾选。证据缺失的条目继续留在研究草稿中。
