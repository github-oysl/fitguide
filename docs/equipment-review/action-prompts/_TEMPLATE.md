# 动作出图模板（v2）

适用[自动流程](../../image-generation-workflow.md)。当前全量迁移和暂停状态见[计划](../../image-generation-plan.md)，动作与配置清单见[_catalog.json](_catalog.json)。本文件允许教学占位符，实际动作文件必须展开；校验器不再接受旧稿豁免。

结构样例：[坐姿绳索划船](cable-row-seated-narrow-grip.md)（单配置）、[腿举](leg-press.md)（分机型条件稿）、[平板支撑](plank.md)（静态、自重）。高位下拉仍有现场证据阻塞，不作为可直接调用的样例。

## 文件头与目录登记

~~~markdown
# <中文动作名> · <英文名>

- 提示词版本：2
- 动作 ID：`<action-id>`
- 器械 ID：<E/B编号；自重为none；未知专机为unconfirmed>
- 工位 / 变式：<station-key> / <variant-id>
- 适配状态：<ready或blocked-evidence；有一个配置阻塞则整文件汇总为阻塞>
- 提示词状态：v2迁移完成（<图示证据已核或条件稿待补证>）
- 图片状态：<未生成或历史样图待复核；本轮未生成>
- 现有数据：<反引号包围的实际源文件名，或建议新增>
- 资料核对日期：<实际核对日期与范围，不改写旧来源访问日期>
~~~

_catalog.json 按 action_id 登记 data_source、prompt_status、image_status 和 variants。每个配置包括 variant_id、station_key、equipment_id、evidence_status、mode、photos（photo编号和仓库相对path）、gap 与 roles（role、status）。当前 prompt_status 为 migrated-v2，角色为 unproduced；仅无器械的 equipment 可为 not-applicable。现有历史样图用 historical-unreviewed 单列，不重新评分或清零计数。清单 generation_enabled=false 表示当前暂停，不是调度开关。

恢复生成时，实际调用与验收记录进入运行 manifest；如需在公共清单记录生成状态，应同步扩展校验和回归用例，不能直接把当前未生成队列改为 complete。

## 一、核对结论

保留动作底稿的教学结论、主辅肌群、技术来源及其实际访问日期，区分历史记录与本轮采用内容。改动解剖或动作结论时核对可靠来源，说明支持哪些断言；通用教程不能证明现场机型或附件适配。训练剂量放页内，不挤进图片。

## 二、器械与空间约束

每个变式独立使用 `### 证据配置 · <variant-id>`，填写下表；不能只在整个文件放一份证据表。照片须先实际打开核对，公开文本仅记录相对路径。

| 项 | 必填内容 |
|---|---|
| 工位键 | 与目录和下方提示词配置一致 |
| 证据状态 | ready / blocked-evidence；ready仅表示图示证据没有关键缺项 |
| 主照片 | 路径、编号、用于核对的结构；未知机型明确缺图 |
| 补充照片 | 路径、编号、补足什么；无补图写理由和限制 |
| 外形不变量 | 框架、座靠垫、颜色、导轨/转轴、配重/挂片等 |
| 人与器械关系 | 朝向、坐站位置、支撑、手脚接触点 |
| 机械关系 | 负载经什么连接到人体，哪些部件移动；未知的明确待核 |
| 附件与模式 | 附件、握法、模式及其证据状态 |
| 不确定项 | 具体缺项；明确是否阻止调用，不用“按通用机型补齐” |
| 相机 | 能看清关键关节、支撑、运动方向的机位和预留范围 |
| 同组固定条件 | 亚洲成年男性、同脸体型、墨绿衣服、机器、光线、背景与裁切 |
| 示范侧 / 镜像 | 单侧示范明确左右；不镜像有方向的机器、附件和文字 |
| 阶段类型 | dynamic / static / cyclic |
| 复用范围 | 物理实例、工位、附件和模式均相同且已有合格空机才复用 |

无器械不等于未知器械：前者 equipment 不适用，后者必须保留 equipment 角色并阻塞。静态动作写进入、保持、退出；循环动作选周期代表阶段，不制造虚假的三段收缩。

## 三、图片提示词

每个变式使用 `### 配置 · <variant-id>`，紧随三个独立元数据行：`- 工位键：...`、`- 证据状态：...`、`- 阶段类型：...`。其下按顺序建立下表的 `#### <role> · <中文标题>`。

| role | 完整提示词应明确的差异 |
|---|---|
| force | 首图；明确发力/保持事实，最多两条绿色方向箭头或稳定提示，短标签和一句口令 |
| equipment | 以已通过force和全部必要实拍锁定机器；移除人物，呈现合理空机状态，无文字/箭头 |
| start | 保持已通过force的人物、工位、机位，明确准备阶段的关节、手脚和移动部件 |
| end | 明确受控终点或退出状态，与start、force可观察地区分，口令包含控制还原提示 |
| error-01… | 连续编号，通常两张；每张只改变一个可见事实，其余保持，红圈定位，附纠正口令 |
| muscles | 独立解剖定位图，只从force继承体型与配色；主肌名称、解剖边界与作用准确 |

每个适用角色恰好一个 text 代码块，完整展开公共约束、附件、人机关系、相机、阶段、短文、输入用途和照片路径；不能写“同上”或残留占位符。代码块应写单张1:1、四边目标8%留白、底部12%不放关键接触点、无Logo/水印、只输出一张；动作图要求全身关键肢体完整，肌群图允许清楚合理的解剖范围裁切。保留角色需要的指导文字，不添加大段解释。

force、start、end 在代码块前逐字记录 `阶段事实：...`，该事实也须完整出现在提示词内。代码块后各写 `验收点：...` 和 `页面配文：...`；提示词用 `底部口令逐字写“...”` 引用同一句页面短文。验收应检查实拍对应、关节/接触、构图、文字与约390px可读性，不能仅复述“画得好”。

每张错误图也写阶段事实，指定对应正确角色，只修改一个实际姿势差异；明确该差异覆盖公共约束中相关正确姿势，避免互相冲突。其页面配文保留错误名和纠正方式。肌群图的验收要区分深浅层，不把深层肌涂在皮肤表面。

无器械的 equipment 只写 `角色状态：not-applicable`、验收点与页面配文，不含 text 代码块。未知专机仍需条件稿，不得伪装成此分支。

blocked-evidence 配置的每个提示词必须以 `执行门槛：blocked-evidence，当前不可调用` 开始，列明具体缺项、补证并修订后才能提交。条件稿可以写已知的动作意图，但不能把尚未确认的结构写为现场事实。

“已通过force”是运行时资产角色引用，不是现存图片。后续实际调用时从该配置 manifest 解析选定路径，按顺序记录实拍、人物锚点与其他参考；力图未通过时不调用依赖图。无照片自重动作不留空的“实拍图2”输入。

## 四、校验与生成记录

提示词完成与图片完成分开。当前不调用生图、不增加attempt、不虚构分数。恢复后每张初次0，最多修正1和2；首图与整套校验共用计数，旧计数保留。记录每个角色版本、依赖、实际输出、五项评分、硬性问题和选定版本；关键缺证不能用8分替代。

## 五、缺项与下一步

每个配置列具体补证项、恢复出图与整套复检要求，同步目录、索引和计划。网页接入独立安排。

完成编辑后运行 `node tools/verify-image-workflow.cjs` 与 `node --test tools/image-workflow.test.cjs`；该检查验证公共文档和配置一致性，不读取被忽略媒体，也不认证技术或生成图片。
