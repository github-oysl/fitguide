# 动作视频处理方案

核对日期：2026-09-18。对象是动作详情里可切换的两路媒体：

- **真人演示** `assets/{id}.mp4`（当前多为 Muscle & Strength 720p 讲解片）
- **3D 动画** `assets/3d/{id}.mp4`（从本地 3D 教学合集整段拷入，见 `assets/3d/manifest.json`）

详情弹窗默认播 3D，用户再切真人。两路对不上、或其中一路夹着片头/合集/错误动作，就会直接教错。动作对比的姿态算法也以真人视频为基准，真人错了会把对比一起带偏。

---

## 1. 问题是什么

### 1.1 3D 和动作对不上

3D 入库脚本 `tools/archive/sync-3d-assets.cjs` 是「一个动作 ID ← 一整份合集文件」，没有按动作裁切。后果有三类：

1. **文件级复用**：不同动作指向同一份字节相同的 mp4。
2. **合集未裁**：一条 30–65 秒视频里连续出现多个动作、营销标题、正误对比。
3. **源动作本身就错**：例如站姿推胸用了夹胸，反向飞鸟用了哑铃飞鸟，坐姿臂屈伸机用了徒手凳上臂屈伸。

已用 SHA-256 确认的 3D 复用组：

| 共用 3D 文件 | 挂到的动作 | 实际画面 |
|---|---|---|
| `三角肌训练组合.mp4` 64.8s | 哑铃侧平举、器械侧平举、器械反向飞鸟 | 片头营销字 → 蝴蝶机反向飞鸟 → 哑铃侧平举 → 绳索面拉 |
| `臀部合集.mp4` 51.7s | 坐姿髋外展、器械髋伸展 | 弹力带髋外展、壶铃 RDL 等，不是坐姿外展机 |
| `坐姿划船.mp4` 25.2s | 窄握绳索划船、挂片坐姿划船、坐姿固定划船 | 三种器械共用一条 |
| `山羊挺背.mp4` 27.7s | 反向背伸展、罗马椅髋伸展、负重背伸展 | 三种器械共用一条 |
| `绳索夹胸.mp4` 28.1s | 站姿绳索夹胸、**站姿绳索推胸** | 画面是龙门架夹胸，推胸完全错配 |
| `绳索二头弯举.mp4` 34.3s | 直杆弯举、绳索锤式弯举 | 附件不同，不能共用 |

| `罗马尼亚硬拉.mp4` 44.1s | 杠铃 RDL、哑铃 RDL | 器械不同 |

### 1.2 真人视频无效信息过多

当前 `assets/*.mp4` 几乎都是 M&S 讲解片，不是循环示范。实测 60 条里 **58 条超过 20 秒**，典型结构：

1. 蓝底英文标题卡（约 0–5 秒）
2. 口播 / 走位 / 调器械
3. 真正的动作循环（通常只有中间十几秒）
4. 片尾或第二机位

动作详情写的是「循环演示 · 无配音」，和实际素材不符。对比功能会把标题卡、讲解、多人入镜算进姿态，识别会漂。

另外还有 **真人文件复用**（字节相同）：

|---|---|---|
| 52.4s | 站姿绳索夹胸、**上斜绳索夹胸** | 都是站姿夹胸 |
| 29.9s | 单臂绳索侧平举、**站姿单臂绳索划船** | 都是侧平举，划船完全错 |
| 43.9s | 坐姿固定划船、**俯身 T 杠划船** | 都是胸托划船机，不是无胸托 T 杠 |

`cable-curl-with-bar`（15.5s）和 `dumbbell-curl`（15.2s）已经收短过，可作为裁切标杆。

## 2. 统一验收标准

两路视频都按这个闸门收，过不了就不要挂到该动作上。

**内容**

- 画面动作、器械、附件、体位必须对应该 ID，不能拿近亲动作顶替。
- 只保留正确示范的完整往返；正误对比、营销字、英文标题卡、口播、走位、调配重全部裁掉。
- 一条视频只服务一个动作。禁止复制同一文件到另一个 ID。

**时长与循环**

- 真人：约 **6–12 秒**，2–3 次完整往返。
- 3D：约 **4–8 秒**，1–2 次正确循环。
- 详情页继续 `loop + muted`。片头一循环就会教错。

**画面**

- `.media` 是 1:1，主体居中，不要大面积黑边或大字幕。
- 封面从裁切后约 30% 处抽一帧，覆盖 `assets/{id}.jpg` / `assets/3d/{id}.jpg`。

**下线规则**

- 3D 合集里切不出该动作 → 从 `GYM_3D_SET` 和 `assets/3d/manifest.json` 撤掉，不要继续展示错误 3D。
- 真人整片动作错误 → 换成正确的 M&S / StrengthLog 条目再裁，不要把错片越裁越短。

推荐裁切：

```bash
ffmpeg -ss START -to END -i SRC.mp4 -c:v libx264 -an -movflags +faststart OUT.mp4
ffmpeg -ss 00:00:01 -i OUT.mp4 -frames:v 1 -update 1 -q:v 2 COVER.jpg
```

裁完后核对：文件哈希不得再与其它动作相同；详情页 3D / 真人切换时器械和轨迹应能对上看。

## 3. 优先级

| 级 | 含义 | 先做哪些 |
|---|---|---|
| **P0** | 会教错：错动作或跨 ID 复用 | 划船/侧平举、推胸/夹胸、髋伸展/三头、T 杠、挂片推胸、3D 合集错配 |
| **P1** | 3D 是合集或正误片，能裁 | 肩部合集、胸部合集、臀部合集、直臂下压、臀桥、辅助引体 |
| **P2** | 动作基本对，只是真人片头/讲解太长 | 其余 M&S 720p |
| **P3** | 缺 3D、分辨率低、变体近似 | 5 个无 3D；侧平举机 / 器械髋伸展 480p |

建议顺序：先修 P0 真人（对比算法依赖它）→ 再裁或下线 P0/P1 的 3D → 批量裁 P2 真人片头 → 最后补 P3。

## 4. 逐动作方案

图例：`裁讲解` = 去掉标题卡和口播，留循环；`换源` = 当前整片动作不对，必须另找正确视频再裁；`切 3D 段` = 从现有合集里切出该动作正确循环；`下线 3D` = 合集里没有对应动作，先撤 3D；`禁止复用` = 不得再复制其它 ID 的文件。

## 5. 和产品行为的关系

- 详情默认播 3D。P0/P1 的 3D 不修，用户第一眼就是错动作或合集广告。
- 对比页文案写「3D 动画正误演示」，姿态算法仍读真人。所以：**真人必须先对**；3D 正误对比可以后做，不要把整段合集当教学循环。
- 若以后要保留正误对比，应拆成独立字段（例如 `video3DGuide`），不要和 `video3D` 混用。
- `docs/muscleandstrength/gym_matched.json` 里若干 `title` 与动作 ID 不一致（髋伸展→三头、划船→侧平举、T 杠→胸托划船等）。换源时同步改匹配记录，避免下次 `sync-ms-assets` 再覆盖回来。

## 6. 建议工期

按「先停损、再裁切、再补缺」：

1. **停损（P0）**：解绑所有跨 ID 复用；错动作 3D 先从 `GYM_3D_SET` 拿掉，详情只留真人，避免继续展示夹胸当推胸、侧平举当划船。
2. **换源 + 裁切（P0 真人）**：单臂划船、绳索后踢、T 杠、上斜夹胸、哑铃 RDL、坐姿推胸机、胯下拉。
3. **3D 合集切片（P1）**：肩部 / 胸部 / 臀部 / 背阔肌合集按时间轴切出唯一正确段，写回 `manifest.json` 的 `source` 与入点出点。
4. **批量裁 P2 真人**：标题卡 + 口播统一切掉，封面重抽。
5. **P3**：5 个缺 3D 的动作有合适源再补；480p 两条换 720p。

验收时每个动作打开详情：3D → 真人各看一遍，确认器械、附件、体位一致，且循环里不再出现蓝底标题或「首先做某某动作」类合集导语。
