# 动作教学图自动生成流程（v2）

本文件是 FitGuide 后续动作出图的执行入口。适用于固定器械、组合绳索工位、自由重量、自重和有氧动作；执行者负责生成、视觉校验、修正和交付，全程无需用户逐张批准。新指令覆盖旧文档中“正确 01 先确认”和“禁止全部图内指导”的规则。

- 编写或迁移提示词：读 [模板](equipment-review/action-prompts/_TEMPLATE.md) 和 [完整样例](equipment-review/action-prompts/lat-pulldown-with-pronated-grip.md)。
- 排队、恢复任务：读 [工作计划](image-generation-plan.md)。
- 查阅评分、错误案例、证据不足和重试处理：读 [注意事项](image-generation-notes.md)。
- 页面展示与图形规格：读 [素材规范](image-generation-prompts.md)。

## 1. 建立动作与器械证据包

读取目标动作文件的一、核对结论，再读取 [器械档案](equipment-review/photo-audit/equipment-inventory.md) 和 [动作映射](equipment-review/photo-audit/exercise-catalog.md)。核对目标动作是否确实存在于网页数据；提示词目录也包含建议新增动作，不能直接当成线上动作库。

每个动作记录：action_id、equipment_id、station_id（组合架工位）、variant_id、附件、主照片与补充照片的仓库相对路径、每张照片证明什么、未确认的结构、来源和访问日期。先实际打开照片，再写提示词。有器械实拍时用参考编辑，不用纯文生图替代现场机型。

完成条件：知道人朝哪里、坐/站哪里、手脚与垫接触哪里、运动部件怎样连接和运动；关键事实可由实拍或可靠原机资料支持。仅“类别置信度高”不代表具体摆位已确认。

若缺图、身份/模式/关键附件未明，标记 blocked-evidence，列出缺项，继续队列里证据充分的其他动作。先用已有资料查找和交叉核对；确实无法补足时在交付中汇总。通用示意只能作为单独标记的概念草稿，不能冒充现场成品。

## 2. 填写一套提示词与验收目标

使用 v2 模板。每段提示词对应一张图片，具有明确输入角色、固定条件、阶段变化、图中文字、验收点。提交模型前展开所有公共块与占位符，记录实际调用的完整提示词。

| 资产角色 | 用途 | 默认要求 |
|---|---|---|
| equipment | 单独器械识别 | 空机，真实外形，关键结构完整，无教学箭头；同一确定工位复用 |
| start | 正确起始 | 明确准备/起始姿势 |
| force | 发力讲解，也是首图 | 正确代表阶段 + 方向箭头/接触提示 + 一句口令 |
| end | 正确结束 | 明确收缩终点或该动作结束姿势，和起始/发力有可见差异 |
| error-01… | 错误示例 | 通常两张，每张只突出一种可见错误，可按需要调整 |
| muscles | 主要锻炼肌群 | 独立定位讲解图，有准确名称、位置与作用 |

无器械动作将 equipment 标记 not-applicable 并说明，禁止捏造机器。静态动作的 force 展示保持姿势及稳定要点；start/end 可解释进入与退出，不能虚构动态收缩三阶段。有氧循环动作定义一个周期的代表阶段，不强套“拉到胸前”等力量动作语言。单侧动作记录示范侧及镜像规则，不随意翻转有方向的器械。

完成条件：所有需要的角色列齐；阶段可用具体关节、接触点、移动部件区分；主要肌群有证据。数量随动作配置计算，默认七张不是固定配额。

## 3. 先生成并校验发力图

第一次仅生成 force，输入真实照片与必要的动作/风格参考，并明确各自用途。已有同工位空机图可辅助，但不能取代实拍。不要先生成其余同组图。

打开实际输出，与原始照片及动作依据逐项比较。按注意事项中的硬性否决项和五项评分检查，不以提示词内容推定图片做到了。发力图必须同时满足：器械/姿势关键项通过、评分不低于 8/10、箭头与文字正确、手机尺寸可读。

未通过则进入第 5 步的修正循环。首图达到两轮修正上限仍失败，标记 failed-limit，停止该动作剩余图片，继续其他可执行动作。关键证据不足则 blocked-evidence，不能用评分消除不确定性。

完成条件：保存 force 的选定版本、原图引用、逐项证据、分项评分和局限。这一步由代理判定，不等待用户确认。

## 4. 生成其余图片并整套初检

将通过的 force 作为人物、器械、光照和机位参考，生成 equipment、start、end、各 error 和 muscles。同一已确认工位的合格空机资产存在时复用，不重复生成；模式或附件改变影响识别时另建配置，不能只按 E 编号强行合并。

代理可批量调用互不依赖的图片生成任务，每张仍单独调用、保存和验收。肌群图只继承人物体型/配色，不需要继承示范姿势和机器。其他图重复固定条件，只改当前阶段所需部分。

逐张全尺寸查看，再以约 390px 手机显示检查文字、遮挡、箭头、接触点；将三张正确图并排比较阶段差异，错误图与最相近的正确阶段对照。检查整套器械结构、座位朝向、附件、握距、示范侧、人物和裁切一致性。

完成条件：每张有 pass/fail/blocked、分项评分及具体原因；依赖某个错误锚点的图片一并列为受影响。

## 5. 有限修正循环

每张资产初次生成为 attempt=0，最多修正两次（attempt=1、attempt=2），合计最多三次有图结果。首图修正与整套复检共用这一个计数，不能到了批量阶段重新归零。更换提示词、机位、模型或回退旧版本不会增加预算。

每轮：记录失败事实 → 只针对问题修改提示词并保留正确不变量 → 生成新版本 → 打开新图重新校验 → 检查对整套的影响。不能机械重复原提示词。更换锚点后检查全部依赖图；需要重生的依赖图各自计数。

没有返回图片的工具错误记录为 technical-error；允许一次相同请求重试，仍失败标记 blocked-tool，避免无限调用。已有图片的低质量输出必须计入修正次数。

到上限仍低于 8 分或存在明显错误：标记 failed-limit，保留失败原因，不混入合格交付。可以选择先前已经通过的版本，但必须复核它与最终整套兼容。整套缺必需图片时状态为 partial，不能宣称完成。

## 6. 交付与恢复

每个动作在本地 output/imagegen/<run-id>/<action-id>/ 下保存：选定独立图片、实际 prompts、manifest.json、audit.md，以及可查看原尺寸的图片索引。工位空机可在 run 级 equipment/<station-key>/ 复用，通过 manifest 引用。

manifest 至少记录：schema_version、action_id、equipment_id、station_id、variant_id、来源相对路径与作用、每张 role/attempt/path/status/scores/reasons、anchor_version、依赖关系、selected、未验证细节、整体状态。计数先落盘再恢复任务；文件名不覆盖旧版本，如 force-v0.png、force-v1.png。

交付报告列合格项、失败/阻塞项、实际修正次数及遗留问题；更新计划对应行动行。只有必需角色全部通过、无关键证据缺口、整套复核通过才标记 complete。视觉评分不是生物力学测量或原机认证。

公开仓库保存流程、模板、队列和去除本机信息的校验结论。实拍原图、含本机绝对路径的运行记录按本地素材管理，不强行添加被忽略文件。提交时显式列出此次交付路径；正式网页接入属于后续独立任务。
